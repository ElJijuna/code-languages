# ROADMAP — `code-languages`

> A zero-dependency, tree-shakeable TypeScript library that exposes structured metadata for programming languages, compatible with Node.js and browser environments.

---

## Vision

`code-languages` solves a simple problem: there is no canonical, typed, npm-installable source of truth for programming language metadata. Developers building IDEs, syntax highlighters, documentation sites, developer tools, or learning platforms always end up reinventing the same data layer.

This library provides that layer with:

- **Subpath imports** — import only what you need, nothing more
- **Full TypeScript types** — zero guesswork, first-class DX
- **Universal** — works in Node.js, Deno, Bun, and any modern bundler
- **Tree-shakeable** — bundlers drop unused language data automatically
- **Community-driven** — easy PR template to add or improve languages

---

## Language Interface

Every language exported from this library satisfies the `Language` interface defined in `src/types.ts`:

```typescript
export interface Language {
  /** Display name. e.g. "TypeScript" */
  name: string;

  /** URL-safe identifier. e.g. "typescript" */
  slug: string;

  /** One-line summary, max 160 characters. */
  description: string;

  /** Rich multi-paragraph description in plain text. */
  longDescription: string;

  /** ISO 8601 date of first public release. e.g. "2012-10-01" */
  publishedDate: string;

  /** All file extensions associated with the language. e.g. [".ts", ".tsx"] */
  extensions: string[];

  /** Original author or organization. e.g. "Anders Hejlsberg / Microsoft" */
  author: string;

  /** Official website URL. e.g. "https://www.typescriptlang.org" */
  website: string;

  /** Programming paradigms. e.g. ["object-oriented", "functional", "imperative"] */
  paradigms: string[];

  /** Latest stable version at time of last data update. e.g. "5.4.5" */
  version: string;

  /** URL to the official language logo or icon. */
  logo: string;
}
```

## Usage

```typescript
// Import a single language (tree-shaken — only this module is bundled)
import { typescript } from 'code-languages/typescript';

console.log(typescript.name);          // "TypeScript"
console.log(typescript.extensions);    // [".ts", ".tsx"]
console.log(typescript.paradigms);     // ["object-oriented", "functional"]

// Import multiple languages
import { javascript } from 'code-languages/javascript';
import { python }     from 'code-languages/python';

// Import everything (not recommended for browser bundles)
import * as languages from 'code-languages';
```

## Build & Tooling

| Tool | Purpose |
|---|---|
| `tsup` | Bundler — dual ESM + CJS output, per-language entry points, .d.ts generation |
| `vitest` | Test runner — ESM-native, fast, no extra config |
| `biome` | Linter + formatter — single tool, zero-config |
| `husky` + `commitlint` | Enforce conventional commits on every local commit |
| `semantic-release` | Automated versioning + npm publish based on commit history |

### `tsup.config.ts` (design target)

```typescript
import { defineConfig } from 'tsup';

export default defineConfig({
  entry: {
    index: 'src/index.ts',
    'languages/typescript': 'src/languages/typescript.ts',
    'languages/javascript': 'src/languages/javascript.ts',
    'languages/python':     'src/languages/python.ts',
    'languages/rust':       'src/languages/rust.ts',
    'languages/go':         'src/languages/go.ts',
  },
  format: ['esm', 'cjs'],
  dts: true,
  splitting: false,
  clean: true,
  treeshake: true,
});
```

### `package.json` exports map (design target)

```json
{
  "exports": {
    ".": {
      "import": "./dist/index.js",
      "require": "./dist/index.cjs",
      "types": "./dist/index.d.ts"
    },
    "./typescript": {
      "import": "./dist/languages/typescript.js",
      "require": "./dist/languages/typescript.cjs",
      "types": "./dist/languages/typescript.d.ts"
    },
    "./javascript": {
      "import": "./dist/languages/javascript.js",
      "require": "./dist/languages/javascript.cjs",
      "types": "./dist/languages/javascript.d.ts"
    },
    "./python": {
      "import": "./dist/languages/python.js",
      "require": "./dist/languages/python.cjs",
      "types": "./dist/languages/python.d.ts"
    }
  }
}
```

> Each new language added to the library requires a matching entry in both `tsup.config.ts` and the `exports` map.

## Semantic Versioning Strategy

This library uses [semantic-release](https://semantic-release.gitbook.io/) with [Conventional Commits](https://www.conventionalcommits.org/).

### Commit → Version mapping

| Commit prefix | Example | Version bump |
|---|---|---|
| `feat:` | `feat: add Ruby language` | **minor** `x.Y.0` |
| `fix:` | `fix: correct Python publishedDate` | **patch** `x.y.Z` |
| `docs:` | `docs: improve TypeScript description` | none |
| `chore:` | `chore: update biome config` | none |
| `BREAKING CHANGE:` | rename `longDescription` field | **major** `X.0.0` |

### `.releaserc.json` (design target)

```json
{
  "branches": ["main"],
  "plugins": [
    "@semantic-release/commit-analyzer",
    "@semantic-release/release-notes-generator",
    ["@semantic-release/changelog", { "changelogFile": "CHANGELOG.md" }],
    "@semantic-release/npm",
    ["@semantic-release/github", { "assets": ["CHANGELOG.md"] }],
    ["@semantic-release/git", {
      "assets": ["CHANGELOG.md", "package.json"],
      "message": "chore(release): ${nextRelease.version} [skip ci]"
    }]
  ]
}
```

## GitHub Actions Workflows

### `ci.yml` — runs on every PR

```
Trigger: pull_request → main
Steps:
  1. Checkout
  2. Setup Node 20
  3. npm ci
  4. biome check (lint + format)
  5. tsc --noEmit (type check)
  6. vitest run (tests)
  7. tsup build (verify dist compiles)
```

### `release.yml` — runs on push to main

```
Trigger: push → main
Steps:
  1. Checkout (with full history: fetch-depth: 0)
  2. Setup Node 20
  3. npm ci
  4. npx semantic-release
Secrets required:
  - NPM_TOKEN   → Settings → Secrets → Actions
  - GITHUB_TOKEN → provided automatically by GitHub Actions
```

## PR Template — Adding a Language

File: `.github/PULL_REQUEST_TEMPLATE.md`

```markdown
## Language: <Name>

<!-- Link to the official website or Wikipedia article as your primary source -->
**Source(s):** 

---

### Checklist

#### Data file
- [ ] `src/languages/<slug>.ts` created
- [ ] All required fields are present and non-empty:
  - [ ] `name`
  - [ ] `slug` (lowercase, URL-safe, matches filename)
  - [ ] `description` (≤ 160 characters, factual, no marketing language)
  - [ ] `longDescription` (at least 2 paragraphs)
  - [ ] `publishedDate` (valid ISO 8601 — `YYYY-MM-DD`)
  - [ ] `extensions` (array, each starts with `.`)
  - [ ] `author`
  - [ ] `website` (valid HTTPS URL)
  - [ ] `paradigms` (at least one entry)
  - [ ] `version` (latest stable version)
  - [ ] `logo` (stable HTTPS URL, SVG preferred)

#### Wiring
- [ ] Named export added to `src/index.ts`
- [ ] Entry added to `entry` in `tsup.config.ts`
- [ ] Entry added to `exports` in `package.json`

#### Quality
- [ ] `vitest run` passes locally
- [ ] `biome check` passes locally
- [ ] `tsc --noEmit` passes locally

#### Commit message
- [ ] Commit follows Conventional Commits: `feat: add <Language> language`
```

## How to Contribute

The fastest way to grow this library is to add a language via a PR. Follow the [PR template](.github/PULL_REQUEST_TEMPLATE.md) and the steps in [CONTRIBUTING.md](CONTRIBUTING.md).

Each new language is a `feat:` commit → triggers a **minor** version bump automatically on merge.
